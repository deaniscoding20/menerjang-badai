# Phase 3 development — task preparation subset

Source task management tersambung dari React → same-origin Go HTTP → application use case → adapter PostgreSQL. Ini **subset development**, bukan klaim seluruh Phase 3 lulus. Website2023, proxy dan profile Hermes tidak diubah; aplikasi belum di-deploy.

Yang tersedia dalam source:
- Create draft, list/filter brand, detail, edit brief/prioritas/metadata agen dan tenggat opsional.
- Komentar/klarifikasi manusia append-only, author dari session, audit atomic; tidak mengubah lifecycle atau menjalankan agen.
- Dependency task same-brand: list/version snapshot, tambah/hapus dengan optimistic version, penolakan self/cycle, history dan audit atomic. UI detail menampilkan daftar prasyarat, candidate satu brand (maks500), tambah/hapus dan conflict reload manual; live DB belum diverifikasi.
- Penugasan langsung ke salah satu dari enam ID registry stabil; tidak wajib melalui Claudia.
- Draft → ready, ready → assigned bila agent dipilih, cancel; terminal tidak dapat dibuka kembali.
- Version integer untuk optimistic concurrency: PATCH/transition tanpa versi terbaru mendapat409.
- Tabel `tasks` dan `task_events`, transaksi atomic state+history+audit dan query-time org/brand grant checks.
- Frontend board/list mencakup semua sepuluh status agar pekerjaan tidak menghilang dari tampilan.
- Backend human-imported deliverable berversi: raw output immutable, parser v1 tujuh kind, validation status, list/detail API, current task version dan audit. UI import/list/detail sudah terintegrasi; integrasi hasil agen/revision-request workflow belum tersedia.

Migration000006 dan deferred DB fixtures tersedia tetapi belum dijalankan; review persistence selesai tanpa blocker; race parent-transition→revision-submit sudah ditutup dengan synchronous mutation ref, regresi RED→GREEN dan review ulang independen tanpa findings (lihat [snapshot status](DEVELOPMENT-STATUS.md)).
- Runtime `mb-dashboard` dan admin CLI explicit migrate/provision; lihat [local development](14-local-development.md).

Yang **belum tersedia**:
- Hermes dispatch/correlation/result/cancel/retry; status eksekusi sengaja ditolak, bukan dipalsukan.
- Worker/outbox/Temporal durable workflow, pause/resume/replay/restart proof.
- Human assignee dan eksekusi request-revision workflow; human revision-request notes tersedia, tetapi tidak ada loop agen/approval/resume. Dependency execution gate menunggu workflow nyata.
- Klarifikasi tersimpan sebagai catatan manusia; integrasi request/response dan resume runtime belum tersedia.
- Knowledge/assets/approval/publishing/analytics integrasi live.

## HTTP contract

Semua route memerlukan opaque server session. Mutasi juga memerlukan exact same-origin Origin + X-CSRF-Token. Authority berasal dari session server, bukan `org_id`, `requester_id` atau role di body/query. Unknown fields ditolak. Role owner/administrator/marketing_manager/editor boleh menulis, tetap dengan explicit brand grant; viewer/analyst/approver hanya membaca.

- `GET /api/tasks?brand_id=<uuid>` → `{items: Task[]}`. Tanpa filter hanya task dari brand berizin. Batas development500 rows terbaru; pagination belum diimplementasikan.
- `POST /api/tasks` →201 Task. Body: brand_id, title, objective, instructions, priority (low|normal|high|urgent), agent_id opsional/null, deadline_at opsional/null (RFC3339 dengan zona waktu). Status awal selalu draft.
- `GET /api/tasks/{id}` →Task.
- `PATCH /api/tasks/{id}` →Task. Body: version wajib; title/objective/instructions/priority/agent_id/deadline_at opsional. `deadline_at` omitted mempertahankan nilai; null menghapus; string RFC3339 memperbarui tenggat. Brand tidak dapat dipindah. `agent_id:null` menghapus penugasan metadata. Perubahan agen pada task ready/assigned menyesuaikan status assigned/ready; draft tetap draft.
- `POST /api/tasks/{id}/transition` →Task. Body: status, version, reason opsional. queued/running/waiting_input/waiting_approval/completed/failed mendapat409 execution_disabled.
- `GET /api/tasks/{id}/dependencies` →`{version,items:[{task_id,title,status}]}`. Source version dan dependency list berasal dari satu SQL snapshot. Same org+brand saja; tidak dibatasi pagination pada graph.
- `POST /api/tasks/{id}/dependencies` / `DELETE /api/tasks/{id}/dependencies` →200 Task. Body keduanya `{dependency_id,version}`; mutasi hanya draft/ready/assigned oleh write roles. Self invalid422; cross-brand/tidak terlihat404; cycle409 `dependency_cycle`; stale409 `version_conflict`. Perubahan nyata menaikkan task version tanpa mengubah status dan mencatat event+audit. Duplicate add/missing delete dengan versi terbaru no-op; versi lama tetap ditolak.
- `GET /api/tasks/{id}/deliverables` →`{version,items: DeliverableSummary[]}`; latest100 revisions descending, metadata saja, source task version dari snapshot sama. Pagination belum tersedia.
- `POST /api/tasks/{id}/deliverables` →201 DeliverableVersion. Body `{raw_output,version}`. Human import oleh write roles pada draft/ready/assigned, bukan callback agen. Raw wajib nonblank UTF8 tanpa literal NUL, maksimum128KiB; request JSON maksimum1MiB untuk escape overhead. Raw dipertahankan persis. Structured v1 sah diberi `validation_status:validated`; malformed/unknown-schema/escaped NUL diberi `invalid` dan structured null. Kedua jenis import menaikkan task version dengan event+audit, **tidak** status/approval/dispatch. Author/ID/revision/origin dibuat server; origin selalu human_import.
- `GET /api/tasks/{id}/deliverables/{deliverableID}` →record immutable dengan raw_output dan structured/null, dibatasi parent task+record+org/brand ACL. Tidak ada update/delete/import agen pada subset ini; human revision-request dicatat lewat endpoint terpisah tanpa mengubah output lama.
- `GET /api/tasks/{id}/revision-requests` →`{version,items: TaskRevisionRequest[]}`. Latest100 catatan descending created_at,id dengan parent version dari satu snapshot; adapter single-SQL snapshot sudah terintegrasi, belum dijalankan pada DB nyata.
- `POST /api/tasks/{id}/revision-requests` →201 TaskRevisionRequest. Body `{deliverable_id,body,version}`; exact immutable deliverable dari org+parent task yang sama (termasuk historical/raw-invalid); author/revision/ID/time dari server. Body trim Go White_Space,1–4000 Unicode codepoints,UTF8/noNUL; request64KiB untuk overhead escaped supplementary Unicode. Current write role,task draft/ready/assigned,current version wajib; stale409,hidden target404. Record+parent version+history/audit harus atomic, status tidak berubah. Ini hanya human feedback, tidak dispatch/retry/resume/approve/reopen atau mengubah output lama. Persistence/UI sudah terintegrasi di source dan fixtures; live DB/browser acceptance tetap belum dijalankan.
- `GET /api/tasks/{id}/events` →`{items: TaskEvent[]}`. Urut version, maksimum1000; pagination belum tersedia.
- `GET /api/tasks/{id}/comments` →`{items: TaskComment[]}`. Urut created_at,id, maksimum500 catatan pertama; pagination belum tersedia dan batas ditampilkan UI.
- `POST /api/tasks/{id}/comments` →201 TaskComment. Body: body (teks biasa, trim, 1–4000 Unicode codepoints), kind opsional (`comment` default atau `clarification`). Unknown fields, forged author/org/id dan kind approval ditolak. Tidak ada edit/delete catatan pada subset ini.

Task mencakup id, brand_id, requester_id, title, objective, instructions, priority, status, agent_id (empty string jika tidak ada), version, deadline_at (null atau RFC3339), created_at, updated_at. Organization ID tidak diserialisasi. Events mencakup id/task_id/actor_id, event, from_status/to_status, version/reason/time. Update biasa juga menghasilkan event walaupun status tidak berubah.

401 berarti perlu login;403 akses/CSRF ditolak;404 resource tidak terlihat/tidak ditemukan;409 stale version atau disabled execution;422 domain invalid;503 dependency unavailable. Error SQL/provider tidak dikirim ke browser.

Assignment adalah perencanaan pekerjaan, bukan bukti agen online atau telah menerima pekerjaan. Tombol Jalankan task disabled. Tidak ada auto-publish atau AI result sintetis.

## Persistence dan migration

`db/migrations/000002_tasks.sql` menambah tabel, index, permission dan memperluas audit event allowlist. `000003_task_collaboration.sql` menambah nullable timestamptz deadline_at, task_comments, FK org+task dan org+author serta audit event task.comment_added. `000004_task_dependencies.sql` menambah graph dengan dua composite FK org+brand+task, constraint no-self serta allowlist history/audit dependency. Adapter memperoleh advisory transaction lock org+brand sebelum task/ACL row locks agar dua edge berlawanan tidak bersama-sama lolos cycle check. Recursive UNION mengecek keterjangkauan sebelum INSERT; semua graph writers harus mengikuti protokol ini. Direct SQL bukan jalur mutasi yang didukung. Migration tidak otomatis saat serve. Jalankan explicit admin migrate hanya setelah menyiapkan database development/disposable dan secret refs; jangan pakai database produksi sebagai fallback.

Mutasi mengunci current task serta membership/role/grant/brand/user/org terkait, memeriksa current role dan version, kemudian menyimpan state+event+audit dalam satu transaksi. Foreign keys mengikat task ke org+brand dan requester ke membership. Read queries menyaring explicit grants, active membership/user/org. Tidak ada blanket owner ACL bypass.

Brand archived tetap dapat dibaca jika grant valid. Mutasi task existing saat brand archived perlu kebijakan final; saat subset ini query lock membaca status brand namun belum melarang seluruh edit existing. Jangan memperlakukan ini sebagai policy final atau acceptance passed.

## Human-imported deliverables: batas perilaku

`000005_task_deliverables.sql` menambah `task_deliverable_versions`, unique org/task/revision, FK task/author dan immutable row trigger untuk UPDATE/DELETE. `lockTask` menserialisasi alokasi revision serta current role/version; import, task version, task event dan audit commit atomic. Submitted revision baru tidak mengubah revision lama. List latest100 tidak membawa body; detail memerlukan parent task dan record ID yang cocok. SQL/migration/trigger ini belum dijalankan pada DB nyata.

`000006_task_revision_requests.sql` menambah append-only `task_revision_requests`, composite FK org+task+deliverableID+deliverable_revision, author membership FK, timestamp/ID index dan immutable UPDATE/DELETE trigger. Target revision diturunkan server dari output existing; tidak menerima revision/author dari body. `lockTask` memeriksa current write role/grant/state/version; insert note, saveTask version dan event+audit commit dalam transaksi yang sama. List version+latest100 notes berasal dari satu statement. Deferred DB fixtures tersedia di `task_revision_requests_test.go`, belum dijalankan. UI disclosure memuat panel saat pertama dibuka dan mempertahankan state sesudah ditutup; target summaries hanya dimuat saat composing, pilihan historical/raw-invalid eksplisit dan tidak memakai task version sebagai fallback ketika snapshots berbeda.

Validated hanya berarti lolos envelope/schema v1, **bukan** kebenaran fakta, approval, hasil agen terpercaya atau ready-to-publish. Malformed output tetap raw-only dan jelas invalid. Import manual bukan bukti agen berjalan; asal agent/correlation/attempt harus ditambahkan melalui bridge terautentikasi terpisah nanti, tidak menerima claimed agent author dari payload. Perubahan revisi tidak menyetujui konten atau menyelesaikan task. Revision-request conversation, approval bind exact version dan agent result ingestion masih deferred. Raw output dan section body harus dirender plain escaped text, bukan HTML/Markdown execution. Human import belum punya idempotency key; stale optimistic version mencegah pengulangan submit pada versi task lama, tanpa auto-retry mutation.

## Tenggat dan komentar: batas perilaku

Tenggat hanya metadata, bukan scheduler/reminder/dispatch otomatis. Tahun valid2000–9999; tanggal lampau boleh dicatat. UI memakai waktu lokal perangkat dan menampilkan zona waktunya; update brief tanpa menyentuh tenggat mempertahankan instant asli termasuk detik/milidetik. Tenggat yang diubah dikirim sebagai RFC3339 UTC. Stale edit tetap409.

Komentar hanya catatan manusia. Klarifikasi tidak menandai waiting_input, melanjutkan workflow, memberikan approval atau menyelesaikan task. Author/time/ID dibuat server dan adapter memakai session actor, bukan nilai payload. PostgreSQL append+audit berada dalam satu transaksi dengan current role/grant dicek kembali. Catatan boleh ditambahkan pada task terminal; tidak membuka lifecycle kembali. Brand archived mengikuti keterbatasan policy existing di atas. Tidak ada deduplication/idempotency POST komentar; pengiriman ulang manual dapat membuat dua catatan. UI tidak melakukan auto-retry POST.

Test disposable baru mencakup persist/clear deadline, stale update, comment+audit, unchanged task version/status, current-role downgrade dan revoked grant. **Belum dieksekusi terhadap PostgreSQL**. Kasus live tambahan tercatat di [checklist](testing/DEFERRED-CHECKLIST.md) bagian T02.D/T02.C.
